# 1. 修订目标

- 本次修订基于前期评审意见，将原“gRPC 单接口调试 MVP”升级为“gRPC 协议完整接入接口测试体系”。

- UI 与交互必须贴合 MeterSphere 现有接口测试模块：调试、定义、用例、场景、报告，不做割裂的 gRPC 工具页。

- 复用 MeterSphere 已有 AI 生成用例流程，不单独新增 gRPC AI 模块；只扩展 gRPC 协议上下文构造、proto 校验和用例同步适配。

- 支持 proto 文件模式作为 V1.0 主路径；Server Reflection 作为 V1.1 能力规划，避免第一阶段范围失控。

- 输出内容要能直接指导 Cursor 分阶段执行，但阶段 0 必须先补齐真实源码路径。

| **官方对齐依据：**MeterSphere V3 接口测试包含调试、定义、场景、报告；接口调试支持服务端执行和本地执行；接口定义用例页已有 AI 生成与同步用例流程。因此 gRPC 应以协议扩展方式融入现有链路。 |
|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

# 2. 产品定位

**目标定义：**在 MeterSphere 社区版接口测试模块中，将 gRPC 作为与 HTTP 并列的协议类型，支持接口定义、proto/schema 管理、调试、用例、场景自动化、断言、变量提取、AI 生成用例和报告展示。

| **不推荐做法**           | **推荐做法**                                      | **原因**                                   |
|--------------------------|---------------------------------------------------|--------------------------------------------|
| 新增“gRPC 调试”独立菜单  | 在现有接口定义/用例/场景/报告中增加 protocol=GRPC | 避免割裂，贴合 MeterSphere 原有交互        |
| gRPC 单独一套 AI 入口    | 复用现有“用例 → AI 生成 → 同步用例”流程           | MeterSphere 已有 AI 能力，二开只需协议适配 |
| 只支持临时调试不落库     | 支持保存接口定义、用例、场景步骤和报告结果        | 自动化测试必须可沉淀、可回归               |
| 每次执行实时依赖远端反射 | 执行使用已保存 Descriptor 快照                    | 保证历史用例稳定性                         |

# 6. 功能需求

## 6.1 协议类型扩展

- 新增 protocol 字段或等价枚举，支持 HTTP、GRPC。

- HTTP 旧数据必须默认按 HTTP 处理，不能因 protocol 为空报错。

- 所有列表、详情、用例、场景、报告通过协议标签区分。

## 6.2 Schema 来源与 proto 管理

- V1.0-A 支持上传单 proto 文件并解析 Service/Method。

- V1.1 支持多 proto/import、Server Reflection、proto 版本管理。

- 保存接口定义时必须保存 Descriptor 快照或可重建 Descriptor 的 proto 内容，自动化执行不得只依赖临时上传文件。

## 6.3 gRPC 接口定义

- 用户新建接口时选择 gRPC 协议。

- Service/Method 必须来自 proto 或反射解析结果，不允许纯手填。

- Streaming Method 展示但置灰，提示当前版本暂不支持。

## 6.4 gRPC 调试

- 支持服务端执行和本地执行；127.0.0.1 表示实际执行进程所在环境。

- 支持 Metadata、环境变量、请求 JSON、超时时间。

- 响应展示 grpcStatus、duration、responseJson、errorCode、errorMessage。

## 6.5 gRPC 用例

- 调试结果可保存为新用例、覆盖已有用例或复制为新用例。

- 用例保存 Metadata、requestJson、timeout、断言、变量提取。

- 接口定义变更时，沿用 MeterSphere 用例同步/差异提示机制。

## 6.6 场景自动化

- 场景步骤新增 GRPC_REQUEST。

- 支持 HTTP 与 gRPC 混合编排。

- gRPC 步骤支持变量替换、前置/后置脚本、断言、提取、失败停止策略。

## 6.7 报告展示

- 报告步骤列表显示 gRPC 协议标签。

- 步骤详情展示 Service、Method、Metadata、requestJson、grpcStatus、responseJson、断言结果、提取变量。

- 报告分享、导出、删除复用现有报告机制。

## 6.8 AI 生成用例支持 gRPC

- 复用 MeterSphere 现有 AI 生成入口：用例页 → AI 生成 → 预览 → 同步用例。

- 系统自动将 proto、Service、Method、字段结构、枚举、repeated、嵌套对象作为 AI 上下文。

- AI 生成结果必须通过 proto Descriptor 校验，用户确认后才能同步入库。

## 6.9 权限、日志、安全

- 发送 gRPC 请求属于执行行为，应校验执行/调试权限。

- 日志记录调用人、项目、执行方式、目标服务、Service、Method、耗时、结果，不默认记录完整请求/响应。

- Metadata 中 authorization/token/secret/password/api-key 等字段日志和报告默认脱敏。

# 7. AI 生成用例交互

入口：接口定义 → gRPC 接口详情 → 用例 → AI 生成

弹窗内容：

当前接口：\[gRPC\] com.demo.UserService / GetUser

生成要求：用户自然语言输入

生成设置：正常场景 / 异常场景 / 边界值 / 枚举覆盖 / 空值缺失字段

Metadata 模板：authorization: Bearer \${token}

数量：3~10 条

生成结果：

表格展示用例名称、类型、请求 JSON、断言、风险提示、proto 校验状态。

用户勾选后点击“同步用例”，选择模块并保存。

| **AI 边界：**AI 生成的是用例草稿，不得自动启用或直接批量入库；不得编造真实 token；不得将敏感 Metadata 明文传给外部模型。 |

# 8. 关键业务规则

| **规则**       | **说明**                                                                |
|----------------|-------------------------------------------------------------------------|
| 请求 JSON 类型 | 前端编辑器与后端 DTO 统一按 String 保存和传输，内容为合法 JSON 字符串。 |
| 空请求体       | 允许使用 {}，支持 EmptyRequest 或空 message。                           |
| Metadata       | V1.0 支持普通 ASCII Metadata；不支持 xxx-bin 二进制 Metadata。          |
| 变量替换       | 执行前先解析环境变量、场景变量、前置脚本变量，再进行 JSON 转 Protobuf。 |
| 超时           | 默认 10000ms，建议范围 1000ms~60000ms。                                 |
| 响应大小       | 默认最大展示 5MB，超过后截断展示并提示。                                |
| 删除保护       | 接口被用例、场景、测试计划引用时，删除前提示影响范围。                  |
| proto 更新     | 重新上传 proto 后需提示影响接口、用例、场景；V1.1 支持 proto Diff。     |
